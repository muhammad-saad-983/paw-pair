# Ticket T06 — Rule-backed recommendation engine

## Data inputs and outputs

`src/pawpair/recommender.py` reads `data/processed/association_rules.csv` (generated by T05) and `data/processed/item_frequency.csv` (generated by T03). `recommend.py` provides a CLI so we can test and demonstrate the engine before building Streamlit in T07. The raw dataset and prior pipeline remain unchanged.

## Matching algorithm

1. Receive a basket of **product IDs** and validate IDs against the observed pet-product catalog.
2. For each mined rule with a **single-item consequent** `A → {B}`, check whether all antecedent items are in the basket (`A ⊆ basket`) and whether `B` is not in the basket.
3. Group qualifying rules by consequent ID `B`.
4. Sort each item's rule evidence by confidence, observed joint basket count, lift, and antecedent length (all descending). The first rule is that item's **best evidence**.
5. Rank products by best evidence using the same ordering; break final ties deterministically by product ID. Show the best evidence and, optionally, other matching rules. Do **not** add confidence across rules.
6. If nothing qualifies, explicitly show no rule-backed recommendations. No popularity fallback is used; a fallback would need to be separately labeled.

**Why single-item consequents?** The confidence of `A → {B,C}` refers to purchasing *both* B and C, not B individually. Splitting such a rule into recommendations for B and C while displaying its original confidence would be misleading. These rules remain accessible to the future rules explorer but are excluded from item-by-item recommendations.

**Why confidence first?** It estimates the observed conditional proportion of joint orders among orders containing the antecedent, unlike raw support which can favor very popular products. Basket count breaks ties in favor of more observed evidence; lift measures relative association strength and is a tertiary tie-breaker. The evidence base is still small, so this is a documented heuristic, not a calibrated probability or claim of causal relevance.

## Smart basket and what-if

`engine.make_basket(ids)` returns a `SmartBasket` with `add(product_id)`, `remove(product_id)`, `recommendations(limit)`, and `preview_remove(product_id)`. `preview_remove()` is nonmutating and returns full **before/after/gained/lost/retained** recommendation sets. A removed product may become a new recommendation because it is no longer in the basket; that is expected.

`engine.recommend(ids)` and `engine.compare(before, after)` are pure operations that can be reused with Streamlit session state. Full-set comparisons avoid artificial changes caused solely by truncation to top-N display slots.

## Real dataset demonstration (0.2% min support, 30% min confidence)

```bash
python recommend.py --basket 24508 5938 --remove 5938 --limit 5
python recommend.py --basket 15190 --limit 5
```

- Basket products `24508` (Classic Ocean Whitefish & Tuna Feast Cat Food) and `5938` (Savory Salmon) trigger `14492` (Classic Seafood Feast Cat Food), with the joint three-product rule supported by **7 baskets**, support approximately **0.2565%**, confidence **100%** for that particular antecedent, and lift around **129.95**. This is **not** strong evidence of general performance: only seven baskets are involved.
- With `5938` removed, the same product `14492` is still suggested by `24508 → 14492`: joint count **13**, support approximately **0.476%**, confidence **65%**. Item `5938` can itself appear as a new suggestion because it has left the basket.
- Basket product `15190` (Prepared Meals Savory Rice & Lamb Stew Dog Food) recommends `12902` (Prepared Meals Beef Stew Wet Dog Food), based on **7 baskets** and **70%** confidence for that direction.

These are *observed associations between variants*, not necessarily useful cross-category complements. T09 will manually classify rules for usefulness/triviality/uncertainty.
